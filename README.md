# HC initiation during norepinephrine support

**研究目标：在感染评估记录支持、正在使用去甲肾上腺素（NE）的成人ICU患者中，比较当前启动氢化可的松（HC）与当前暂不启动、随后接受通常照护的院内死亡风险。**

本仓库管理HC研究的代码、执行清单与研究决定。现有MIMIC实际首剂主分析保留；新增MIMIC医嘱分析与eICU医嘱分析各自重新定义资格、起点、风险集和调整。不是“曾用过HC与从未用过HC”，也不是完整疗程、固定延迟政策或已确认全部患者符合Sepsis-3感染性休克。

当前阶段：**已有MIMIC主分析和eICU补充估计，正在解决两者能否形成同一临床问题下可解释的证据。** 代码能够运行不等于已验证因果识别；结果方向一致也不是阶段通过条件。

## 已完成的证据

|分析|记录与目标|院内死亡风险差，百分点〔区间〕|状态|
|---|---|---:|---|
|MIMIC-IV3.1主分析|实际HC首剂节点、启动者ATT式比较；约250次启动、风险集约4,080位患者|−2.47〔−7.72, +2.87〕|原500次患者bootstrap结果保留|
|eICU-CRD2.0补充|HC医嘱节点；约480次启动、3,840位独立对照、约50家贡献启动节点的医院|+7.64〔+3.63, +11.49〕|100次患者正权重bootstrap，初步不确定性|
|eICU严格录入时钟|相同队列与行动，改变可用调整信息|+7.57〔+3.22, +11.32〕|与主口径并列|
|eICU NE剂量可解释子集|同时限制启动者及对照，目标人群改变|+6.52〔+2.08, +11.01〕|选择性敏感性，不替代主口径|

MIMIC实际首剂和eICU医嘱估计暂不能直接合并或称为同协议外部验证。eICU主口径最大绝对SMD为0.086，对照患者ESS约1,143，最大单人权重份额0.54%；但局部病情相似性、NE剂量的医院性缺失和临床用药目的仍有限制。未调整与调整后RD由约+19.8变为+7.6个百分点，提示病情选择对比较很重要，不能将剩余关联直接解释为HC造成伤害。

eICU普通患者重抽样的可计算性检查在100次中有70次产生空对照池，NE子集71次。已报告区间使用在首个eICU死亡比较前保存的归一化Exp(1)患者正权重方案，每次重拟合；三个口径各100次、无优化失败或警告。它条件于现有观察支持，不修复缺乏对照，也不等同MIMIC普通重抽样区间。扩大重复次数仅稳定数值精度，不增加临床信息。

## 为什么这样规划

|当前依据|必须先做的工作|避免走回的弯路|
|---|---|---|
|eICU medication明确是医嘱，并不保证实际执行；MIMIC有POE、处方及eMAR三种时刻 [1,2]|先在MIMIC内部建立独立医嘱队列，再看与实际首剂的联系|把时间字段改名后直接拼接两库|
|旧MIMIC处方缓存只覆盖约4,350次原风险集住院，而成人NE来源约15,010次住院|对旧范围之外的住院补取必要医嘱资料|以后来实际启动者及其旧对照决定新的医嘱研究资格|
|两库点估计方向不同，且此前结果均已看过|固定比较问题与全部分析口径，先解释人群、来源和时间差异|调窗口、亚组或模型以追求相同方向或显著性|
|整体SMD较小，但部分医院NE剂量缺失、部分局部风险集支持弱|报告医院记录结构、局部支持及选择性；分别说明可测与不可测混杂|只展示整体平衡后宣布识别成立|
|Rajendran等有双库合并、处方来源的先例，但其CEDAR另作验证 [3]|借鉴来源协调与分别评价，再判断是否有汇总意义|将“使用两个库”本身当作创新或外部验证|
|TARGET要求交代目标试验、数据映射与识别假设 [4]|以实际代码完成试验映射与解释边界|只靠标题或格式把观察性关联升级为治疗建议|

### M1 · MIMIC医嘱来源和独立风险集（当前优先，1–2个有效工作日）

- [x] 保存独立来源协议：使用全部成人NE来源；首次原生关联IV HC医嘱；不按未来执行、取消、存活或停药成功入组。
- [ ] 在原缓存范围外补取系统激素处方与必要POE键，记录字段、过滤、字节数、耗时和完整读取检查。
- [ ] 在医嘱时点重新判断NE、此前感染证据、实际及医嘱激素历史，区分冲突、未提取与未记录。
- [ ] 由全来源建立同NE经过时间的未启动对照，保留后续允许启动的通常照护比较。
- [ ] 按变量回看窗核对既有病情缓存是否覆盖新起点；只有能改变判断的缺口才定向补取。
- [ ] 纳入索引前治疗限制与关键病情资料后，确定最终分析风险集；不把技术候选称为临床核验人群。

**完成标准：**资格无需未来治疗行为；对照来源不继承旧实际给药选择；身份、时钟和医院结局链可解释。记录未知可以保留为明确状态，不能用缺失指示替代核心治疗含义。若医嘱时刻本身无法表达一个合理决策，只停止这项桥接的因果主张，不改写冻结主结果。

**读取预算：**当前已授权的两张CSV合计约8.0 GiB，仅投影所需字段；这不等于只读取对应字节。此阶段不默认扫描chartevents、labevents或全部eMAR。确需补取时，先以风险集缺口说明价值。

- [ ] 固定MIMIC医嘱分析的调整集、风险计算和不确定性方法，再读取新分组死亡差异；已看过其他结果的事实保留。

- [ ] 只有临床策略、资格和目标人群能够协调时，才讨论汇总；分别报告是允许的最终方案。

**完成标准：**能够解释每个估计究竟代表谁、哪一种治疗决定及哪些假设。方向不同不自动判失败，方向相同也不自动通过。若核心定义仍不可协调，保留独立补充结果，不强称同协议外部验证或把两库人数相加当证据升级。

### M3 · 完善推断与有限敏感性（约3–5个有效工作日）

- [ ] 复核小风险集下的不确定性方法，明确患者所有住院及多种风险集角色共享权重、每次重拟合预处理与评分。
- [ ] 区分患者抽样、固定医院支持与推广至新医院三种不确定性；不以医院数多就自动声称可推广。
- [ ] 方法确定后，将必要区间扩至至少500次并检查端点Monte Carlo稳定性；记录全部失败和警告。
- [ ] 固定报告严格时钟、NE剂量可解释子集、未知结局界限及已指定的大医院影响，不搜索最有利版本。
- [ ] 针对HC用途和未测病情制定一个可解释的定量偏倚情景；不把它当作消除混杂的证明。

**完成标准：**结果及区间能够复核，重要限制在实际估计范围内可说明。若比较明显依赖缺乏支持的状态，则停止扩大其死亡因果解释，保留观察证据；不自动换问题、阈值或结局。

### M4 · 一篇完整临床稿件（通过M2–M3后，约2周）

- [ ] 以同一个HC启动问题组织Methods、Results及TARGET映射，原主结果不替换为更显著的结果。

- [ ] 对照直接激素近邻，明确首剂节点、医嘱决策和跨来源证据各自的增量，不以TTE或双库本身宣称创新。
- [ ] 完成可复现入口、数据访问与源码来源说明、统计核查及作者审阅。
- [ ] 根据完成后的证据决定首投。首选候选JIC；Annals of Intensive Care为同档备选，Journal of Critical Care为更保守备选；当前不承诺录用或一区。

## 代码、运行与数据边界

|文件|用途|
|---|---|
|`README.md`|研究问题、阶段证据、计划与验收条件|
|`hc_order_bridge.py`|本轮新增的独立医嘱来源、资格和风险集；直接在此维护|
|`analysis/steroid_*.py`|既有四个HC主脚本的配置化源码导出；通过同步命令更新|
|`analysis/hc_paths.py` / `config.example.json`|机器路径配置；不读取数据即可导入|
|`sync_sources.py`|明确源码名单的同步；仅变更路径声明并检查其余语法树相同|
|`test_hc_contracts.py`|合成边界与患者加权测试，不需要受限数据|

运行环境沿用Python3.8.20、CPU、NumPy1.23.5、pandas1.2.5、SciPy1.10.1、scikit-learn1.3.0；未安装或升级依赖。

```powershell
python -X utf8 -m unittest -v test_hc_contracts
python -X utf8 hc_order_bridge.py --help
```

使用获准访问的本地资料时，复制`config.example.json`为忽略的`config.local.json`，填写文件位置；也可用`HC_TTE_CONFIG`指定文件。当前新入口按顺序运行：

```powershell
python -X utf8 hc_order_bridge.py plan
python -X utf8 hc_order_bridge.py project
python -X utf8 hc_order_bridge.py evaluate
python -X utf8 hc_order_bridge.py support
```

已完成的投影自动复用。新增分支保存在原私有`hc_poe_linkage.pkl.gz`，不写入冻结的`steroid_sequential.pkl.gz`。报告继续复用原`steroid_tte.md`，会议HTML及Word主稿不是本轮自动发布对象。

**当前复现边界：**干净检出可跑合成测试；实际分析需要获得授权的原始数据及现有派生缓存。四个历史脚本的部分原始提取阶段仍依赖既有NE元数据和旧提取模块，尚不是任意机器从全库CSV一条命令完成全部历史主分析的发布包。各阶段完成后逐项解除依赖，不为建仓库重建全库平台。不要对未知来源的pickle使用本工具。

旧HC源码继续在原项目路径维护；`sync_sources.py`将明确允许的四个文件导出到仓库，原文件不迁移、不删除，统计代码不改动。版本控制记录每次同步和新增桥接工作。远端私有，不添加任何数据、不邀请第三方、不自动公开或提交论文。

## 依据

1. MIT-LCP：[MIMIC POE](https://mimic.mit.edu/docs/iv/modules/hosp/poe.html)、[prescriptions](https://mimic.mit.edu/docs/iv/modules/hosp/prescriptions.html)、[eMAR](https://mimic.mit.edu/docs/iv/modules/hosp/emar.html)。原生键与各时间字段必须分别映射。
2. MIT-LCP：[eICU medication](https://eicu.mit.edu/eicutables/medication/)。医嘱不必然反映实际给药，医院接口存在差异。
3. Rajendran等，Nature Communications2025：[原文](https://pmc.ncbi.nlm.nih.gov/articles/PMC12075795/)、[固定代码版本](https://github.com/surajraj99/Corticosteroids-in-Patients-with-Critical-Illness/tree/e96952407e38b52807ecd521372eeb005c993f1f)。MIMIC＋eICU合并开发、CEDAR验证；其MIMIC处方来源不证明本地医嘱等于执行。
4. Cashin等，TARGET：[正式报告规范](https://jamanetwork.com/journals/jama/fullarticle/2837724)。用于报告设计和观测数据映射，不替代识别假设的评价。
5. Rubin1981：[Bayesian bootstrap](https://doi.org/10.1214/aos/1176345338)。提供Dirichlet随机权重的一般基础；本研究患者共享权重与风险集应用需另行说明。
6. 期刊定位：[JIC](https://link.springer.com/journal/40560)2025JIF7.5；[Annals](https://www.em-consulte.com/revue/AICOJ/presentation/annals-of-intensive-care)6.9。投稿目标不作为分析选择依据。
